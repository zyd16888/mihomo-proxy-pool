# 规则分流、观测与出口 IP 探测

用户确认实施：在固定节点监听之外增加规则监听入口，合并多份订阅规则，并提供请求日志、连接视图和出口 IP 探测。

- [x] 规则监听：同一张监听表增加出口方式，规则监听不绑定节点，可与固定节点监听并存并互相切换。
- [x] 内置策略组与规则集：国内直连、国外代理、广告拦截，按排序值决定优先级，内核按间隔自动更新并支持手动刷新。
- [x] 合并多份订阅的规则、策略组和规则集，处理策略组重名、规则集重名与磁盘路径冲突、规则去重与优先级。
- [x] 配套 DNS：国内解析器为主，出境规则集走国外解析器，节点域名单独解析。
- [x] 观测：内核日志窗口与连接视图，把生成标识还原成页面上的名称。
- [x] 出口 IP 探测：按节点和按监听，来源 `ip9.com.cn`。
- [x] 旧数据库升级、行为测试、真实内核校验、浏览器验证和文档。

## 边界与取舍

规则分流只在存在启用中的规则监听时生成，未使用时不下载任何规则集，也不把兜底从 `MATCH,REJECT` 改开。

订阅的 GEOIP / GEOSITE 规则默认丢弃。这类规则会让 `mihomo -t` 下载约 13 MB 的 GeoIP 和 GeoSite 数据库：实测校验耗时从 65 毫秒变成 10 秒以上，超出应用流程的校验超时，离线环境直接失败。内置规则集用 `rule-set:` 覆盖同样范围，DNS 策略同样避开 `geosite:`。需要时可在设置中打开，代价是首次应用明显变慢。

规则集下载本身经过规则引擎，因此默认 `proxy: DIRECT`。经代理下载时，节点不可用会导致规则集始终拉取失败。

策略组名字过滤（`filter` / `include-all` / `use`）在生成配置时展开为具体成员：生成配置把所有节点改名为 `node-<id>`，按名字过滤在内核里匹配不到任何东西。

内核不会为成功建立的连接输出命中规则的日志，因此请求走向以连接视图为准，日志用于 DNS、失败原因和内核事件。

出口探测通过被测出口自身发起查询，失败时不退回直连，避免把不通的节点显示成可用。按节点探测使用仅监听回环的内部端口和独立策略组，不影响承载实际流量的监听；探测串行并保持约 1 秒间隔，符合查询服务每个来源地址 60 次/分钟的限制。

日志、连接和探测结果都只保存在内存，管理服务重启后清空；三者都不写数据库、不增加配置版本、不触发重载。

## 验收

- 空规则监听端口可被浏览器直接使用，国内域名直连、国外域名走节点、广告域名被拒。
- 固定节点监听行为不变，两类端口并存。
- 多份订阅重名策略组不互相覆盖，规则集不共用磁盘路径。
- 关闭规则分流前必须先停用规则监听。
- 旧数据库升级后监听端口、绑定和引用保护均不变。
